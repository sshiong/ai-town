# 持久访客等待队列

满额时，管理员可允许来自已核验邻居的访问申请进入有界持久队列。Host 配置与每次 Home 申请都须明确允许等待；旧配置和旧客户端继续拒绝后重试。队列默认关闭；开启时默认上限 50、最长等待 120 秒、来源轮转，单来源等待上限默认不限。允许配置 1–1000 个候补、1–3600 秒、单来源 0–1000 或不限。单来源等待上限与实际访客占用配额是独立预算。

等待状态保存在原 `visitLedger` 的 `QUEUED`，沿用原 visitId、双方 deployment epoch、authority epoch、租约版本和 fencing；新消息 `VISIT_QUEUED` 经过原签名、Inbox/Outbox、序列和业务回执。Home 明示 `allowQueue` 与队列协议版本 1 后，Host 才发送新类型。重复申请、重复消息和重启不能刷新位置或截止时间。已有访问身份的重复 `VISIT_RESERVE` 在序列拒绝前也必须核验身份与 fencing，不能用新消息 ID 绕过授权。

等待不创建预留、地图访客、远程决策或模型任务。Home 保留唯一旅行授权，地图冻结仅发生在合法预留确认后。等待期限取 Host 配置与 Home 原已签发租约的较早值，等待会消耗旅行授权时长；暂停不延长期限，Host 不能自行延长 Home 租约。名额释放、定时恢复及管理员“Check admission”触发相同事务准入检查。

FIFO 选择最早仍有资格的候补；来源轮转按持久的上次获准来源游标循环，来源内部保留 FIFO。来源暂停/配额阻塞不会阻挡其他有资格来源。既有候补优先于新申请占用同一名额。每次预留重新检查信任、允许访问、双向探测与 epochs、身份冲突、维护锁、租约、总名额、预留名额、来源配额以及模型/决策/事件预算；批准动作不能绕过这些条件。CPU/RAM 尚未接入真实阈值采集，仍公开为 null，不把队列检查当作硬件容量认证。

管理入口位于 Town administration：Town 页配置/汇总，Travel & visitors 页显示候补名称、来源、原截止时间、原因，并支持暂停、恢复、拒绝及公平推进。Home 手动与自主访问分别明确授权等待。自主策略更新使旧授权的尚未出发请求进入安全取消；手动请求保留。撤销邻居信任终结 Host 候补；关闭 outbound 取消对应 Home 请求。暂停邻居/inbound 关闭停止提名，原等待期限仍生效。公开 capabilities 只有签名的计数与策略，不泄露姓名、居民 ID、来源明细、模型或 fencing。

取消、到期、关队列、撤信、identity/epoch 冲突沿已有清理证明与安全返乡规则。Host 未创建实体的候补终结为 `REJECTED + cleanupConfirmed` 并发 `VISIT_CLEANED`；Home 有认证清理证明才恢复，失联时等待原授权租约及安全余量。通信队列满额不能回滚本地终结。公平 drain 每批终结与晋升共用最多 20 次转换预算，接收新申请前后两次 drain 共用剩余预算；其余候补由后续定时 reconcile 继续处理。关闭队列及邻居策略清理分批调度，避免每个清理通知扫描通信队列时超过单次事务预算。资源配置变化写审计，普通/大/选择性备份验证新可选字段，旧包继续兼容；活跃候补作为既有非终态阻止未排空迁移，克隆不会复活原访问授权。

## 本机真实验收

2026-10-10，A/B/C 是独立持久 Convex 后端，Chat 使用本机 `qwen3.5:4b`，Embedding 保持 `qwen3-embedding:0.6b` 与原 profile。Host A 临时设为 0 名额，B/C 各一份真实居民申请都在两端进入 QUEUED，无预留、访客实体、决策或候补模型工作。暂停 B 后 A 开放 1 名额并推进，原 C 请求进入 ACTIVE；C 清理返乡释放名额，恢复 B 后原 B 请求进入 ACTIVE，再安全返乡。期间没有为候补重新生成访问 ID。另实测 B 的候补取消及 C 的 5 秒候补过期，都在认证清理后恢复 Home。原三镇居民 ID、固定 Chat 绑定及 Chat/Embedding profiles 一致，原准入配置恢复。私有结果为 `visitor-queue-live-proof.json`，不将凭据/模型原文日志放入仓库。

Host 与 Home 的真实进程重启追加演练已执行两次，均证明同一候补的原位置与截止时间持久，且暂停 B 时 C 可获准入场。首次 B 在后续检查前到期；第二次 B 恢复后的 ACTIVE 等待超时。两次整条重启后依次入场链均未通过，不能把持久化子项替代完整恢复验收。最终清理后 A/B/C 居民全部 HOME_ACTIVE，模型绑定不变；超时原因仍在诊断。

专项事务测试覆盖无实体等待、旧协议/默认兼容、并发名额与预留预算、FIFO 和持久来源轮转、来源配额跳过、队列/来源边界、管理员权限与暂停/取消、期限/lease、关闭/撤信/epoch/身份冲突、零预算与积压、维护、失去回执、通信满额、Home 非法确认与迟到消息，以及沿原 Saga 从候补到入场和返乡。模拟事务证据不替代真实所有阶段崩溃、网络分区、多来源长期负载或公网拓扑验收。完整方案还需选择性包冷档实体自动打包、超大冷档分块与热冷腾挪/压缩/外部位置、主机健康和完整故障/压力矩阵。

本批全量回归为 43 组、542 项通过；随后仅对邻居撤信清理补共用 16 条预算与两项 47 请求混合恢复测试，资源专项最终 30 项全部通过。Convex/前端 TypeScript、构建和 lint error 检查通过，保留原 Vite 大包提示。320px 浏览器实测弹窗内容宽度与滚动宽度均为 266px，无横向溢出。部署后再次核验 A/B/C 全部居民在 Home、D 克隆保持停用，既有大型冷文件精确再导出仍通过。
