# 选择性归档与导入

管理员的 Data & backups 面板支持单居民、所选居民、配置、原始记忆、历史五种分项归档，与完整小镇备份并存。新格式 v2 为签名的 selective-transfer；旧 v1 仍可核验和审计，但不能导入。分块按持久检查点处理，没有 500 条记忆的静默截断。

导入前关闭联邦入口、停止目标引擎、结束访问并排空已排队工作。每个居民显式选择克隆、合并、恢复或跳过；Chat Profile 显式映射、创建待配置草稿或跳过，不能回退到 main。克隆产生新的本镇居民身份。合并必须证明目标属于本镇，保留目标人格与固定模型。原 Home 恢复还须核验身份、声明源已停机，并确认覆盖计划。

签名和全部分块摘要、所有者、时间/类别筛选、引用闭包先完成预检。记忆跨所有者的外部证据须显式映射或跳过引用；不能导入非记忆的外部引用。选择跳过一个包内居民时，其他居民指向其记忆的边也必须明确处理。旅行和传输记录仅作为历史来源存档，不能重放权限、访问、发言或邻居信任。

预检展示原始数据量、向量空间与 embedding 调用估算。实际修改前保存目标快照，管理员提交匹配的计划和目标摘要；中断可从持久检查点恢复，部分应用后取消会先删除本次新记录，再恢复原目标记录和 ID。导入完成与向量构建分别报告，向量失败可重试，不能误报已可召回。

## 2026-10-10 验证

- 12 项导入测试覆盖 530 条 canonical memory、循环引用、外部所有者隔离、显式模型映射、原身份恢复、向量清理、错误计划摘要、失败恢复和部分回滚。
- 隔离 C 的实际 v2 归档含 8 个分块、8 条记录；独立核验签名与摘要后导入完成。克隆获得新的 global/player/agent ID，原两位居民及其固定 Chat 绑定、Chat/embedding profile 均保持不变。该归档没有 canonical memory，因此不把这次实测当作真实 embedding 重建证明。
- 第二次实际导入推进到 REMAP 后取消；确认中途克隆确实存在，随后回滚恢复全部原 world/resident/profile/binding/memory 记录及 ID，并释放维护锁。
- 实际浏览器 320px 下新导入面板可见，页面宽度 320px、弹窗内容宽度 296px，无横向溢出；文件选择到确认提交的完整浏览器流程尚未作为实测证据。

私有报告保存在本机实验目录，密钥与归档内容不提交仓库。这是分项交付证据，完整方案的三镇同名、身份公钥链和长期压力等仍继续验收。
