# 小镇身份公钥轮换与人工恢复

正常轮换保留 townId、居民身份、部署代数、访问租约和邻居共享凭证。管理员声明操作者与理由，生成新签名钥，并以旧、新两把钥共同签署公开证书。每个当前受信邻居收到 PREPARE 后，用随机挑战核验新私钥的持有；所有邻居准备成功后，本地原子激活新钥，删除旧私钥，发出双签名 activation。

准备期内失败或邻居离线不会部分更换受信公钥；到期可安全取消。激活后不可回滚，COMMIT 依靠持久状态持续重试，直到邻居 ACKED。本地 COMMITTED 表示本地已切钥，不等于所有邻居都已确认。邻居提交后立即拒绝普通业务中的旧签名；不可变历史证书可沿已认证双签名链验证。普通 Outbox 保存业务信封，交付时使用当前私钥签名，保持原 messageId、nonce、sequence、权限与期限。

正常身份轮换与共享凭证轮换互斥，避免认证边界同时变化。已撤销、重新配对或更换部署的邻居不能被旧操作重新授权。

旧私钥不可用时走单独人工恢复流程。系统暂停联邦入口，要求访问与工作排空；邻居管理员须通过独立渠道核验具体 fingerprint，并完成新钥随机挑战，才可恢复该邻居身份。界面的旧钥不可用、独立核验和恢复完成确认默认不勾选；恢复默认不启用联邦入口。公开备份中的历史证书不能代替这项核验。

常规和分块备份仅导出公开 federationIdentityKeyHistory。导入保留证书原文，统一设置 verified=false，不能自动建立 live trust。包含暂存私钥的轮换操作表和邻居投递表不导出。

事务测试覆盖三镇双签名挑战与激活、离线邻居准备过期、COMMIT 丢 ACK 后模拟进程重启、伪签名/挑战拒绝、已认证历史链与导入假链隔离，以及人工恢复的独立核验。测试重启会停止原测试运行时的定时器，再由新运行时的 maintenance 从持久状态恢复；这属于模拟重启证据，不能写作实际 Docker 重启验收。2026-10-10 隔离 A 实际激活身份 version 2，B/C 两个当前受信邻居均 ACKED，三个镇的居民身份、固定 Chat/embedding 配置保持不变。轮换后重新完成独立签名探针。实际浏览器显示全部邻居确认，320px 无溢出，人工恢复确认默认关闭。实际 Docker 重启、丢 ACK 和恢复旧私钥缺失仍不作为本次运行证据。
