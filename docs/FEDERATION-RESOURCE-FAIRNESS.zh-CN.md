# 资源摘要与访客公平调度

GET /federation/v1/capabilities 返回短期有效、签名的只读容量摘要：传输和动作能力、接待/预留名额、已占用含等待清理的访客、决策和本地 Chat 队列、限额及准入状态原因。它不包含居民、模型端点、单来源占用、访问授权或任何密钥。CPU/RAM 没有可靠采样时返回 null 和 UNAVAILABLE，不用零值假装健康。

摘要是提示，不授予访问权限；受信策略和 Host 原子预留仍是最终准入检查。计数达到有界扫描上限时明确标识 lower bounds，不承诺虚构的剩余容量。

Host 观测先按来源镇最近获得观测的时间排序，来源内按访客最近观测时间排序，每一轮每个来源取一位访客，避免地图插入顺序与访客数量垄断唯一决策槽。该状态随 world/visitor 保存，不依赖进程内游标。Home 的决策恢复分页越过已被自身 activeDecision 占用的旧工作，不让固定前十条阻塞后续居民。

事务测试覆盖 3 和 10 个合成来源、唯一/多个槽位、序列化后顺序、其他世界的占用和过期租约，以及恢复越过旧阻塞工作。多个独立合成数据库的签名容量摘要属于事务测试，不代表真实 3–10 个 Docker 节点、持续压力或硬件容量承诺。

2026-10-10 三个实际独立本地后端的容量摘要均返回 OPEN，独立核验签名与当前公开身份，CPU/RAM 为 null；这证明真实接口已接通，仍不代表压力或机器容量测试。

本地 Chat 现在按来源轮转，来源内保持 FIFO。原生日常对话、记忆、反思仍作为 local 来源；旅行大脑请求只接受持久决策任务 ID，由当前 RUNNING 任务、有效 Home 访问账本、TRAVELING runtime 的 activeDecision/权限代数以及 TRUSTED Host 推导来源，不接受调用者自报来源。失效授权在领取模型槽位前重新拒绝。

轮转游标存入数据库；旧请求没有来源字段时按 local 处理。等待队列的每来源上限为 max(1, ceil(maxPendingLocalLLM / (受信邻居数 + 1)))，全镇等待上限仍是最终限制。该上限为其他 Host 和本地任务留出空间；增加受信邻居会收紧每来源等待额度，已有请求不会因此被删除。只有一个来源时保留原 FIFO 行为。

绝对排队期限仍为最多 30 秒，HTTP 期限仍为最多 90 秒加 5 秒废弃槽位安全余量；没有延长慢模型的预算，也没有修改模型绑定、提示词、embedding 或原生记忆优先级。7 项事务测试覆盖 3/10 个合成 Host 与本地工作的轮转、来源内 FIFO、配额、伪造/失效授权、游标重载和原期限；数据库状态重载测试不代表真实进程崩溃验收。

接待满额仍采用拒绝并重试，持久的访问排队尚未实现。Chat 公平调度和 Host 观测轮转不能替代访问排队、真实多节点持续压力或硬件容量验收。
