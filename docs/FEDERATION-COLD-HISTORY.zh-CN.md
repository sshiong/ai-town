# 已校验的私有历史文件

历史证据页现在会自动查询对应冷档索引。完成的原生日常聊天，以及已完整接收且 Home 摘要 DONE 的旅行原文，可以创建签名的私有 JSON 文件副本，并分页读取原始文本、消息 UUID、作者与原时间。不会创建公开下载链接；每次发现、创建和读取都要求管理员权限、精确居民绑定及原始记忆的归属验证。

文件的 v1 manifest 记录 schema 版本、来源镇、来源范围、导出时间、条数、字节数和 SHA-256，并由本镇身份签名。创建过程先写文件，再实际回读它、复算摘要并核验签名；发布事务复查源内容未变化后才标记 VERIFIED。未发布快照发生修正时可以重试，已经核验的文件保持不变。响应丢失时不删除尚不能证实未被引用的文件。

来源键还包括会话完成时间；不能仅凭恢复后可能重复使用的世界内 conversationId 误用另一段聊天。旅行来源继续按居民全局身份、Host、访问及完整页核验。原版 `messages` 文本先落库，后续 Tick 才更新 `numMessages`，最后一条原文可能超出该计数；文件保留全部原文，不把原生日常计数当成绝对上界，也不把这样的原文自动标成联邦已执行事实。旅行原文则严格要求连续页、唯一消息 UUID 及精确总数。

当前每个文件最多 1000 条消息、900000 字节，超限明确拒绝，需要后续分块作业；不截断。读取每页最多 25 条，每次回读都验证字节数、摘要和签名。文件缺失、篡改、归属错误和未完成源均不会变成空历史或自动覆盖原文。

这是可读的文件副本，当前仍保留全部热记录和 canonical memory/关系/向量。普通备份继续完整导出原热记录，不把部署私有 storageId 当作可跨部署恢复的文件。冷文件现可独立导出实体并在恢复热原文后显式导入；自动随大/选择性备份打包、NAS/自定义冷档位置、超大历史分块、验证后热数据腾挪和真实压缩尚需接通，不能宣称已降低热存储占用或已完成完整热冷分层。容量配置中的 coldArchiveLocation 字符串不会自动连接外部存储。

## 可携带的签名冷文件与恢复

历史证据页的“Save or restore a history file”可以下载 `ai-town-cold-history-file` v1 JSON，文件包含原 manifest、公钥、签名和原文实体，绝不把部署私有 storageId 当作跨部署数据。文件应与对应居民/小镇备份一起保存。当前小型小镇/居民备份会自动携带已验证的冷文件实体；大/选择性分块包仍需配合独立冷文件。独立文件操作顺序是先恢复居民与对应原文，再在目标记忆的证据页恢复冷文件。

恢复须填写独立核验的源公钥指纹；历史签名密钥与当前公钥可能不同，不能只信文件自报指纹。先核验格式、大小、消息唯一性、摘要、签名和精确目标原文的 UUID/文本/作者集合。恢复插入顺序可能变化，原文件的签名消息顺序和时间始终保留；缺失、额外和重复 UUID 均拒绝。作者 ID 变化必须提供显式一对一映射，旅行还必须匹配原 owner 与目标居民归属。目标消息缺失或不同不会用文件悄悄补造事实；应先完成对应历史备份恢复。导入核验只验证这份文件，不建立邻居信任或授予联邦访问。

预检确认摘要绑定目标居民/记忆、完成会话、当前原文、文件与作者映射；提交事务重新核验，变化须重新审阅。导入实体写入后实际回读校验，失联响应不误删尚未确认的文件。源 manifest/签名/文本/时间保持不变，另存目标查询索引和显式作者映射。恢复后数据库新创建时间不覆盖原消息时间；界面并列显示原作者与映射后的作者。重复导入相同文件幂等，已验证的其他文件不被覆盖。

6 项新增事务测试另覆盖独立数据库中的日常/旅行文件恢复、同一原文件在不同目标世界的索引隔离、指纹/篡改/错误目标拒绝、预检变化和旅行 owner 映射。真实 C→B 这条链不等于自动全镇备份集成、任意大文件、压缩或可安全删除热原文的证明。

## 小型备份自动携带文件实体

小型 `ai-town-backup` v1 包现可携带可选 `coldHistoryFiles`。每份实体含原始冷文件、包内居民/记忆归属和已有作者映射；小镇备份签名覆盖整组实体的条数、字节与摘要。原始历史签名不重签，也不要求其历史来源成为可信邻居。未携带实体的旧包继续兼容；携带实体的包须具备有效外层签名，文件各自签名、原文及归属仍独立核验。包内没有私有 storageId 或密钥。

导出按实际 canonical memory 发现已验证文件并回读物理正文；相同会话在多个记忆下只携带一次。居民导出同时沿会话记忆收集已结束会话与完整消息，避免导入居民没有原版共同参与计数行时遗漏历史。缺文件、签名不符、源原文不完整或不同均拒绝导出，不静默跳过。总包保留 5 MB、500 条原子记录限制，冷实体计入记录与字节预算，实体最多 100 份；单文件仍最多 1000 条/900000 字节，超限不能据此宣称已有大文件支持。

恢复先只读预检，逐份上传与实际回读文件，再在同一数据库事务内恢复 canonical 数据、应用居民/作者映射并发布目标冷档索引。源文件签名、源 ID、原消息顺序和时间保持不变；当地世界/记忆查询使用新索引。任一目标图、作者、消息或实体绑定校验失败，数据库改动整体回滚。发布前失败及已确认发布后未引用的暂存实体可清理；发布调用的响应丢失或结果不明时保留暂存实体，因为一次独立查询不能证明尚在执行的提交永远不会完成。此时可能留下未引用对象，不能把它当作自动垃圾回收或真实崩溃全阶段验收。原热记录继续保留。

## 分块存储发布与回滚的响应丢失保护

全镇与选择性分块导出、导入 manifest/分块和私有回滚快照现统一保留结果未确认的实体。数据库事务可能已经提交或仍在执行，不能因 RPC 抛错删除所引用文件；确认重复上传不采用新实体时，仅删除该次新上传对象。发布前构造/写入失败仍可清理未提交实体。可能产生未引用的暂存对象，这不是自动垃圾回收的验收。失败作业沿已有检查点恢复，完整 manifest 或已接受分块不因此丢失。选择性回滚期间的重复取消保留当前恢复页；回滚失败后再取消会从同一页继续。

9 项新增事务故障测试在实际测试数据库提交后模拟响应丢失，覆盖全镇/选择性导出页和 manifest、导入作业和已接受分块、私有目标快照；导出恢复后所有实体仍可读取，重复分块重试保留第一份，部分应用后取消恢复原数据。另验证回滚一块后的重复取消及失败后取消，恢复原世界、记忆、绑定和 ID。此证据不代表真实网络断开、进程崩溃或全部阶段的恢复矩阵完成；大型与选择性分块包自动携带冷文件仍需接通。
